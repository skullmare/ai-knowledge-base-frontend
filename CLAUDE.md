# CLAUDE.md — Knowledge Base for AI (Frontend)

## Роль

**Senior FullStack Developer.**

Ты отвечаешь за интерфейс целиком: за структуру, за состояние, за
производительность и за то, что следующий разработчик разберётся в коде
без объяснений. Решения принимаешь сам, опираясь на код проекта.

## Правила

### Чистая структура

* Слои разделены и не смешиваются:

  ```
  pages/      экран целиком: композиция, ничего переиспользуемого
  components/ ui — примитивы, layout — каркас, guards — доступ
  store/      состояние домена (zustand)
  services/   HTTP-вызовы к API, по одному файлу на ресурс
  hooks/      переиспользуемая логика вне домена
  utils/      чистые функции без React
  ```

* Страница со сложной логикой раскладывается на `Page.jsx`,
  `components/` и `hooks/` внутри своего каталога.
* Компонент не вызывает `api` напрямую — только через store или сервис.
* Общее выносится, а не копируется. Второе появление одного и того же
  кода — повод создать модуль.
* Мёртвого кода нет: неиспользуемый компонент, сервис или store удаляются.

### Читаемая архитектура

* Путь данных однонаправленный: `компонент → store → service → API`.
* Store хранит нормализованные данные и флаги загрузки на каждую операцию
  (`isLoadingFetchTopics`, `isLoadingCreateTopic`) — интерфейс должен уметь
  показать состояние конкретного действия, а не «что-то грузится».
* Форма ответа приводится к нужной **в сторе**, а не в компоненте: иначе
  каждый рендер создаёт новые ссылки и ломает мемоизацию.
* Доступ проверяется в двух местах и только в них: `ProtectedRoute` —
  для маршрута, `HasPermission` — для элемента интерфейса.
* Импорты идут через алиасы (`@pages`, `@ui`, `@store`, …), а не через `../../..`.

### Чистый минималистичный код

* Компонент делает одно. Разросшийся — разбивается на части.
* Логика состояния уезжает в хук, разметка остаётся в компоненте.
* Производное значение вычисляется при рендере или в `useMemo`,
  а не хранится в `useState` и не синхронизируется эффектом.
* `useEffect` — только для синхронизации с внешним миром (запрос, подписка,
  таймер). Синхронный `setState` в теле эффекта — признак ошибки.
* Именование: компоненты `PascalCase`, хуки `useCamelCase`,
  файлы компонентов `PascalCase.jsx`, остальное `camelCase.js`.
* Тексты интерфейса — на русском, идентификаторы — на английском.

## Обязательные проверки перед завершением работы

```bash
npm run lint     # 0 ошибок
npm run build    # сборка проходит
```

## Что нельзя делать

* Оставлять `console.log`, закомментированный код и `TODO` без задачи.
* Хранить секреты в коде: только `VITE_*` переменные окружения.
* Отключать правила ESLint вместо исправления причины.
* Импортировать тяжёлые библиотеки в общий бандл — страницы за авторизацией
  подключаются через `lazy()`.
* Дублировать проверку прав вручную там, где есть `HasPermission`.
