# Совместное редактирование темы

Содержимое темы правится не через REST, а через WebSocket-соединение
с сервером Hocuspocus на backend. Несколько сотрудников видят правки
друг друга в реальном времени.

## Слои

```
Topic.jsx
   └─ useBlockNoteEditor(id, profile, ready)
        ├─ collaborationService.createProvider(id)   → HocuspocusProvider + Y.Doc
        └─ useCreateBlockNote({ collaboration: { provider, fragment, user } })
```

| Модуль | Ответственность |
| --- | --- |
| `services/collaboration.js` | создание и пересоздание провайдера, аутентификация |
| `pages/topic/hooks/useBlockNoteEditor.js` | связка провайдера с редактором, аватары соавторов, загрузка изображений |
| `pages/topic/hooks/useAutosave.js` | автосохранение названия, категории и ролей темы |

## Подключение

Адрес получается из `VITE_API_URL` заменой схемы `http` на `ws`.
Токен передаётся функцией, а не значением: провайдер запрашивает актуальный
токен при каждом подключении.

Провайдер создаётся с `connect: false` и подключается только после того,
как REST-запросы страницы завершены (флаг `ready`). Иначе установка
WebSocket конкурирует с загрузкой метаданных темы и экран собирается дольше.

## Просроченный токен

```
onAuthenticationFailed
  → POST /auth/refresh
      ├─ успех   → destroy() старого провайдера, создание нового с тем же Y.Doc
      └─ неудача → очистка токена, переход на /login
```

Провайдер именно **пересоздаётся**, а не переподключается: `provider.connect()`
после отказа аутентификации срабатывает ненадёжно. `Y.Doc` при этом остаётся
прежним, поэтому привязка к редактору и несохранённое состояние не теряются.

## Права

Право на запись определяет сервер: при аутентификации он выставляет
`connection.readOnly` для пользователей без `topics.update`. Интерфейс
дополнительно прячет элементы редактирования через `HasPermission`,
но решающая проверка — серверная.

## Изображения в редакторе

BlockNote вставляет изображения из буфера обмена как `data:`-URL. Такой
блок нельзя сохранить в базу знаний: содержимое раздувается, а картинка
не попадает в хранилище.

```
вставка изображения
  → поиск блоков с data:-URL
  → преобразование в File
  → загрузка через store/file (S3)
  → замена props.url блока на публичную ссылку
```

Уже обрабатываемые блоки помечаются в `Set`, чтобы повторный рендер
не запустил вторую загрузку того же файла.

## Автосохранение метаданных

Название, категория и роли доступа сохраняются отдельно от содержимого —
обычным `PATCH /topics/:id` с задержкой в 1 секунду после последнего ввода.

Форма подхватывает данные темы **только при смене темы**, а не при каждом
изменении `currentTopic`. Иначе ответ автосохранения перезаписывал бы поле
ровно в тот момент, когда пользователь в нём печатает.

## Статус темы

Любое сохранение — и содержимого через WebSocket, и метаданных через REST —
возвращает тему в статус `review` и снимает признак индексации. Чтобы правки
попали к ИИ-агенту, тему нужно одобрить заново.
