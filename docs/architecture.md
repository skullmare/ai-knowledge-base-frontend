# Архитектура

## Общая картина

```
┌──────────────────────────────────────────────────────────┐
│                        Компоненты                         │
│  pages/ — экраны        components/ — примитивы и каркас  │
└───────────────┬───────────────────────┬──────────────────┘
                │ читают состояние      │ вызывают действия
                ▼                       ▼
┌──────────────────────────────────────────────────────────┐
│                      store/ (zustand)                     │
│      данные домена + флаги загрузки + текст ошибки        │
└───────────────────────────┬──────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────┐
│                       services/                           │
│         по одному модулю на ресурс REST API               │
└───────────────────────────┬──────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────┐
│              services/api.js — axios-инстанс              │
│   Bearer-токен, автоматический refresh, единая база URL   │
└───────────────────────────┬──────────────────────────────┘
                            ▼
                    Backend /api/v1/*
```

Поток однонаправленный. Компонент никогда не вызывает `api` напрямую —
только действие стора, которое обращается к сервису.

## Слои и их ответственность

| Слой | Что делает | Чего не делает |
| --- | --- | --- |
| `pages/` | композиция экрана, связывание хуков и компонентов | не содержит переиспользуемых компонентов |
| `components/ui/` | визуальные примитивы без знания домена | не ходит в сторы |
| `components/layout/` | каркас: шапка, навбар, таблица, модальные окна | не знает про конкретные экраны |
| `components/guards/` | показ элемента по правам | не решает, что рендерить дальше |
| `store/` | состояние домена, флаги, вызовы сервисов | не знает про React-разметку |
| `services/` | HTTP-запросы к конкретному ресурсу | не хранит состояние |
| `hooks/`, `utils/` | переиспользуемая логика и чистые функции | не зависят от домена |

## Инициализация приложения

```
main.jsx  → StrictMode → App
App       → восстановление сессии → AppRouter + стеки уведомлений
```

`App` при монтировании один раз пытается восстановить сессию:

* есть `accessToken` в localStorage → сразу загружает профиль;
* нет → пробует `POST /auth/refresh` по httpOnly-куке;
* не вышло → помечает store как инициализированный, дальше решает маршрут.

Эффект защищён ref-флагом: в StrictMode эффекты выполняются дважды, и без
защиты уходило два запроса на обновление сессии.

До завершения инициализации `ProtectedRoute` и `HasPermission` не рендерят
ничего — иначе пользователь на мгновение видел бы экран «нет доступа».

## Права доступа

Две точки проверки и обе обязательны:

* **`ProtectedRoute`** — закрывает маршрут целиком. Нет прав → `/403`,
  нет сессии → `/login`.
* **`HasPermission`** — прячет кнопку, действие или колонку внутри экрана.

Права приходят с профилем и лежат в `store/profile`. Проверка на клиенте —
это удобство интерфейса, а не защита: backend проверяет права независимо.

## Производительность

Страницы за авторизацией подключаются через `React.lazy()`. Это важно
из-за редактора BlockNote: он весит больше всего остального приложения,
но нужен только на странице темы.

| | Начальный бандл |
| --- | --- |
| без разделения | ~1.8 МБ |
| с `lazy()` | ~180 КБ, редактор грузится при открытии темы |

## Обработка ошибок

Ошибки не показываются компонентами вручную:

1. store ловит ошибку, приводит её к тексту через `utils/handleError`
   и кладёт в своё поле `error`;
2. `useErrorWatcher` следит за полями `error` всех сторов;
3. `ErrorSnackbarStack` показывает уведомление и очищает поле.

Успешные операции проходят тем же путём через `store/success`
и `SuccessSnackbarStack`.

`handleError` разбирает формат backend: сначала список `errors[].message`,
затем `message`, затем «Сервер недоступен» при сетевой ошибке.
