# Экраны

Каждый экран лежит в своём каталоге и раскладывается по одной схеме:

```
pages/<page>/
├── Page.jsx            композиция: хуки + компоненты
├── Page.constants.jsx  колонки таблиц, наборы полей, справочники
├── components/         части только этого экрана
├── hooks/              данные, фильтры, модальные окна
└── css/                стили экрана
```

Страница не содержит запросов и бизнес-логики: она связывает хуки
с компонентами.

## Вход — `login`, `verify-2fa`, `forgot-password`, `reset-password`

Четыре шага одного сценария:

```
/login            логин + пароль → backend шлёт код на почту
/verify-2fa       шесть полей ввода, автопереход между ними, вставка кода целиком
/forgot-password  запрос письма со ссылкой
/reset-password/:token  новый пароль
```

Экран `/verify-2fa` после успешной проверки делает полную перезагрузку
на `/`, чтобы приложение стартовало с уже установленной сессией.

## База знаний — `topics`

Два режима отображения: каталог (карточки по категориям) и таблица.

| Хук | Ответственность |
| --- | --- |
| `useTopicsData` | загрузка тем, категорий и ролей, пагинация, сборка параметров |
| `useTopicsFilters` | поиск с задержкой, категория, роль, режим отображения |
| `useCreateTopicModal`, `useDeleteTopicModal`, `useApproveTopicModal`, `useArchiveTopicModal` | действия над темой |
| `useCreateCategoryModal`, `useEditCategoryModal`, `useDeleteCategoryModal` | действия над категорией |

Каждое модальное окно — отдельный хук: открытие, поля, отправка и сброс
живут вместе, а страница остаётся разметкой.

## Тема — `topic`

Самый сложный экран: редактор BlockNote с совместным редактированием.

| Хук | Ответственность |
| --- | --- |
| `useTopicData` | загрузка темы, категорий, ролей |
| `useBlockNoteEditor` | провайдер Hocuspocus, редактор, аватары соавторов, загрузка изображений |
| `useAutosave` | сохранение названия, категории и ролей с задержкой |
| `useApproveTopic`, `useDeleteTopic` | одобрение и удаление |

Пока документ не синхронизирован, вместо редактора показывается скелет —
иначе пользователь видит пустой холст и успевает начать печатать в него.

Подробности — [collaboration.md](./collaboration.md).

## Пользователи — `users`

Один экран с четырьмя разделами: сотрудники платформы, роли платформы,
пользователи ИИ-агента, роли ИИ-агента. Раздел выбирается в боковой панели,
поиск сбрасывается при переключении.

| Хук | Ответственность |
| --- | --- |
| `useUsersData` | загрузка данных всех четырёх разделов |
| `useUsersFilters` | активный раздел и поиск с задержкой |
| `useCreatePlatformUserModal`, `useEditPlatformUserModal`, `useDeleteUserModal` | сотрудники |
| `useCreatePlatformRoleModal`, `useEditPlatformRoleModal`, `useDeleteRoleModal` | роли платформы |
| `useEditAgentUserModal` | выдача роли и блокировка пользователя агента |
| `useCreateAgentRoleModal`, `useEditAgentRoleModal` | роли агента |

Пользователей ИИ-агента нельзя создать из интерфейса: запись появляется,
когда человек регистрируется в мессенджере. Администратор только выдаёт роль,
блокирует и удаляет.

## Журнал — `logs`

Таблица событий с фильтрами по событию, категории, автору, статусу
и диапазону дат. Backend отдаёт готовые подписи `actionLabel`
и `entityTypeLabel`, интерфейс не хранит собственный справочник кодов.

| Хук | Ответственность |
| --- | --- |
| `useLogsData` | загрузка записей и пагинация |
| `useLogsFilters` | фильтры и поиск с задержкой |

## Профиль — `profile`

Свои данные, смена аватара, смена пароля и список собственных прав
(`ProfilePermissions`) — сгруппированный по разделам, чтобы сотрудник
понимал, что ему доступно.

| Хук | Ответственность |
| --- | --- |
| `useEditProfileModal` | редактирование данных и аватара |
| `useChangePasswordModal` | смена пароля |

## Служебные — `index`, `not-found`, `access-denied`

Стартовая страница, 404 и экран «нет доступа», на который перенаправляет
`ProtectedRoute` при нехватке прав.
